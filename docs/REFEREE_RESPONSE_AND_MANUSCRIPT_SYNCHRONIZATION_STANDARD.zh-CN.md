# 审稿回复与论文正文同步规范

**状态：** 已采用的共享规范  
**生效日期：** 2026-11-23  
**适用范围：** 采用中央科研规范体系的仓库中的审稿回复撰写、审查、实质性编辑及与论文正文的同步。

本规范规定审稿回复的科学论证要求和文件职责边界，不规定特定物理模型、期刊格式、回复篇幅或项目专属论文管理流程。

## 1. 严格区分面向审稿人的文件与内部文件

### 面向审稿人的正式回复

回复信面向审稿人和编辑。应直接回答审稿意见，并用相关模型定义、推导、数值结果、实验比较和科学适用条件支撑结论。

不得在回复信中加入内部任务分配、待办清单、分支名称、PR、commit、CI 状态、版本管理细节或内部论文同步进度。

### 内部论文同步记录

如果回复信要求论文正文作出对应修改，应在内部清单或变更记录中跟踪。记录准确的正文位置、当前文本、拟修改内容、支撑证据和实际状态。

内部记录不属于面向审稿人的回复。如果任务仅涉及回复信，且不需要修改论文正文，就不要为了形式而创建不必要的同步清单。

除非选定的论文源码确实已经修改并完成检查，否则不得声称已经修订、增加、删除或缩短论文内容。

**区分内部进度并不意味着隐瞒科学限制。** 必须准确说明真实的假设、适用边界、缺失证据和未解决的物理问题。如果现有证据不足以支持拟提出的主张，应收窄主张，而不是把内部项目状态写进回复信。

## 2. 按照审稿人的问题组织回复

对于包含多个子问题的实质性审稿意见，采用两个层次：

1. **总体回复：** 简洁陈述核心答案、模型或研究范围边界，以及下文将分别处理的问题。
2. **逐点回复：** 对每个独立子问题给出充分回答；在可行时沿用审稿人的编号和问题结构。

每条回复先给出直接答案，再解释物理原因并提供判断所需的证据。总体回复中的总结不能替代具体子回复所需的论证。

不要人为制造子问题或编号。如果当前问题仍需要明确说明自身结论和决定性条件，不要仅写“见上文”。当某项推导已在其他位置完整给出时，可以交叉引用，但仍须保留理解当前回答所需的关系式。

## 3. 论证完整性

回复深度应与审稿意见的科学复杂度相称。对于实质性的物理或唯象学问题，应按适用情况检查以下维度：

1. **直接回答与物理原因：** 明确审稿人究竟提出了什么问题，并解释由何种机制、对称性、相互作用或运动学条件决定答案。
2. **公式来源与推导：** 明确关系式来自哪一项拉格朗日量、规范荷、质量矩阵、有效算符、振幅定义、方程或原始文献。展示支撑论证的关键中间步骤，不能只罗列公式。
3. **数值结果与 benchmark 含义：** 给出输入、参数点、归一化、近似、单位、不确定度以及数值实际检验的对象，并解释它支持哪项主张。
4. **实验适用性与模型映射：** 识别相关产生机制、耦合、自旋结构、衰变道、分支比、寿命、接受度和统计定义。说明已发表限制能否直接应用、是否需要重新解释，或在当前假设下是否不能约束所讨论的模型。
5. **独立子问题：** 对每个不同的物理或实验问题给出可识别的答案和对应证据。

这些是论证维度，不是强制要求每条回复写成五段。简单的术语澄清可以很短；涉及模型机制、定量结果或实验限制的主张，则必须提供足够的推导和证据，使其能够被独立检查。

## 4. 编辑时保留独立的科学论证

不能仅因为文字看起来重复就删除或合并内容。措辞相似或使用相同术语，并不能证明两段内容承担相同的科学论证功能。

合并或删除前，必须确认它们表达的是同一物理命题、同一组适用条件和同一种证据功能。应保留以下区别：

- 适用范围不同的独立图、拓扑或计算子集；
- UV 贡献与 EFT 贡献或反项扇区；
- 数值交叉验证实际验证了什么，以及没有覆盖什么；
- 只在特定 benchmark 下成立的近似与更广参数范围内成立的结果；
- 局部计算与完整匹配、可观测量或物理预测。

只有在合并后仍保留必要公式、推理步骤、数值、benchmark、引用、验证范围和适用条件时，才允许合并。

删除或实质性压缩独立物理结论、推导、benchmark、数值结果、验证陈述或适用条件，属于科学内容变更，而不是普通文字润色。变更记录必须说明原始位置、修改理由、替代位置以及对论证的影响。删除独立科学结论、计算证据、验证结果或适用条件前，必须取得作者明确同意。

无法证明内容等价时，应保留两段内容或使用交叉引用。论证完整性优先于表面上的简洁。

## 5. 科学诚信与表达方式

- 保留必要的科学限定；删除不提供新物理信息的重复免责声明。
- 区分“未被某项限制排除”与“已经得到正面证实”或“在指定参数空间内实验允许”。
- 未经推导或明确 matching，不得在不同模型之间移植公式、参数关系或实验限制。
- 不得将条件性 benchmark 表述为一般性结论。
- 不得用将来的承诺替代基于当前证据的回答。
- 不得隐瞒尚未完成的计算。应说明已经成立的部分，并将主张限定在相应范围内。
- 使用正式、直接、以证据为依据的语气。避免防御性长篇解释、不必要的自我批评和泛泛的未来工作陈述。

## 6. 审查与变更记录

对于实质性修改正式审稿回复或其科学论证支撑材料的 PR：

- 明确回复信和论文源码的精确版本；
- 检查实际 diff，而不只是 PR 摘要；
- 对受影响的 Major Comment 和子问题提供修改前后内容保留审计；
- 提供删除/合并台账；若没有实质性删除或合并，应明确写明“无”；
- 核实关于论文修改的陈述与实际论文 diff 一致；
- 区分源码审查、编译、PDF 视觉检查、数值复现、脚本测试和 CI，不得用一种检查冒充另一种检查。

审查者应将台账与实际 diff 对照，检查是否存在未登记的科学内容删除。如果变更删除了独立科学结论、计算证据、验证结果或适用条件，应确认作者是否明确批准。

回复信、内部清单和相关科研文档的审查遵循[科研文档审查规范](DOCUMENT_REVIEW_STANDARD.zh-CN.md)。任务级证据与验收状态遵循[科研质量门](governance/RESEARCH_QUALITY_GATE.zh-CN.md)。
