# 科研任务交接规范

**状态：** 已采用的共享规范  
**生效日期：** 2026-11-23  
**适用范围：** 采用中央规范的项目仓库中的实质性研究任务，以及跨模型/协作者交接

科研任务应当作为一份可复现的任务说明存在，而不是要求接手者从聊天历史或前一个模型的摘要中重新拼凑。科研任务单应明确研究问题、来源、固定约定、假设、独立工作、检查、预期产物和未解决问题。

任务单是执行前的任务定义，不是推导、计算、测试或验证已经完成的证据。完成证据应保存在研究变更记录、专题 README、审计报告、运行清单和/或 PR 中。

## 1. 何时必须填写任务单

以下实质性工作开始前应填写完整任务单：

- 物理推导、匹配计算或论文解释；
- 数值计算、模拟、参数扫描、数据变换或作图；
- 修改生产代码、物理约定、输入数据或验证逻辑；
- 多个模型、Agent、研究人员或协作者之间的独立任务交接；
- 将用于支持基准、科学结论、论文陈述或正式仓库记录的结果。

不涉及科学内容的简单编辑或仓库维护可以不填写，但 PR 应说明原因。历史工作不要求追溯补写任务单；本规范适用于新的实质性工作和后续任务。

## 2. 规范位置与标识

使用[科研任务单模板](../templates/research-task-brief.md)。

- 专题任务：research/<topic>/task_briefs/<task-id>.md
- 跨专题或仓库级任务：research/docs/task_briefs/<task-id>.md

使用稳定 ID，例如 YYYYMMDD-short-kebab-case。从专题 README、Issue 或 PR 链接任务单。分支名、聊天消息和 PR 标题不能替代任务单。

## 3. 必填的十项内容

十项内容都必须填写。不适用时写 N/A 并解释原因，不得留下含义不明的空白。

1. **研究问题：** 一个可回答的问题、研究对象、所需参数/运动学范围、包含与排除的范围，以及任务可能支持的主张层级。
2. **原始来源与材料：** 论文的标题/作者/DOI 或 arXiv 版本及具体公式/页码；仓库路径/分支/完整 commit；数据文件的来源/版本/许可及必要时的 SHA-256。说明无法访问的来源及影响。
3. **Git 基线与版本：** 仓库、分支、完整基线 SHA、相关代码/输入/子模块/软件包版本、工作树状态和精确比较基线。交接时将移动分支名解析为 commit。
4. **约定：** 所有可能改变符号、因子、变量含义或数值的定义。按适用情况包括度规、单位、动量定义、Fourier 相位、Gamma 矩阵、传播子/宽度符号、态/流归一化、耦合约定、自旋平均、对称因子、参考系及角度/能量定义。明确标出尚未解决的约定。
5. **假设与近似：** 模型内容、自由度、参数基准、运动学区域、截断、忽略的贡献和适用范围。区分项目采用的假设与推导或数据确立的事实。
6. **已验证结果：** 只列出具有可识别证据和适用范围的结果。记录主张、基准/范围、代码/输入版本、方法、残差/容差和状态。没有证据的旧摘要只能视为待检查假设。
7. **所需独立推导：** 指定需要从原始文献、定义或数据重新推导的公式/结论，展示中间步骤、符号、归一化和近似。比较目标不能替代推导。
8. **所需数值/技术检查：** 按适用情况指定量纲/单位、解析极限、守恒、符号/归一化、独立比较、收敛、回归、不确定度和输出完整性检查的方法及验收标准。
9. **预期输出：** 路径、格式、元数据、复现命令、测试、运行清单、图、审计记录、PR 和允许得出的结论层级。
10. **未解决问题：** 相互竞争的定义/数值、各自来源、影响、是否阻塞，以及下一项能够区分它们的检查。

## 4. 执行与变更控制

1. 从原始来源独立推导；旧模型输出只能作为线索和比较对象，不能直接作为权威。
2. 不得静默改变约定。若要改变影响物理结果的约定，应记录旧定义、新定义、理由和影响。
3. 将推导与实现分开，并独立检查实现。
4. 尽可能在判断输出前定义相关验收标准。报告实际残差、容差、命令、日志和精确版本。
5. 如实标记失败、部分完成、受阻和未运行的检查。
6. 保存精确源码版本、输入哈希、运行时/依赖、命令、数值设置和输出校验和。
7. 保留历史结果。约定或实现变化应产生新版本结果，不得覆盖旧结果。

如果任务范围、源码版本、假设或约定变化，应增加带日期的变更记录或创建关联的后继任务单，不得静默替换原始任务定义。

## 5. 必须提交的交付记录

接手者应返回：实际解决的问题与范围；独立推导和关键公式；已确认的约定或有理由的偏离；假设与适用范围；数值/技术检查的方法、容差、残差和状态；复用的历史结果及其精确来源；未解决差异和下一步检查；产物路径、格式、校验和、命令和精确 commit/PR；最终科学状态及其支持的具体主张。

## 6. 与其他规范的关系

任务单定义执行前的要求，不替代记录科学变更及其影响的 [Scientific Diff 工作流](scientific-diff-workflow.md)，记录实际运行/结果/验证的 [RCRPS v1.0.1](STRUCTURED_RESULT_DATA_STANDARD_v1.0.1.zh-CN.md)，[计算结果归档规范](CALCULATION_RESULT_ARCHIVAL_POLICY.zh-CN.md)，或项目专属 AGENTS.md、科学约定和领域验证规范。

除非任务单明确要求某个独立工作流运行，否则 CI 仍然是可选的。绿色 CI 标记不能替代任务单要求的推导和检查。
