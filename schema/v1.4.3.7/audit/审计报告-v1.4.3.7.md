## 迁移器已实现
- 默认 dry-run，不修改源记录。
- `--write-staging` 仅写独立 staging 目录；没有 commit 选项，永远不会覆盖源。
- 明确字段映射；`validation_ids` 不猜测目标类型，写入未决项并从候选目标记录移除。
- 未知字段可选择 `quarantine`、`reject` 或 `preserve`；默认 quarantine 并在报告中保留原值。
- 同一源记录与规则版本的映射结果是确定性的。
- 不支持 v1.2 直接跳到 v1.4；需先执行 v1.2→v1.3 链。
- 不会在原始契约载荷不可恢复时伪造新的 TEC hash。

## 跨记录校验器覆盖范围
已实现：明确映射的引用存在性/目标类型/项目一致性、任务与已批准契约一致性、替代身份方法的契约哈希/版本/批准状态/适用来源与存储类型、缺哈希文件的 `needs_review` 规则、目录/文件哈希字段分离、事件序号连续与前驱摘要链接、Artifact Integrity 的选定状态迁移、supports 图自环/有向环检测。

未实现或未完整覆盖：所有多态引用字段、全部状态机命名空间、事件 payload 的 event_sha256 重算、真实文件系统遍历/符号链接/路径碰撞、目录 manifest 从真实目录重算、事务提交和指针回滚、物理科学验收。

## 重要实现边界
目录 manifest helper 只处理受限的 FileEntry schema：字段键固定为 ASCII、大小为整数或 null、不允许浮点数。它不是通用 RFC 8785 实现；helper 一律拒绝符号链接。正式采用前应引入/验证符合 RFC 8785 的实现并加入公开黄金向量。当前 helper 不读取磁盘目录，因此不能证明实际文件与清单一致。

## 新发现的模式缺口
`state_transition_event` 的 `record_id` 缺少独立的目标记录类型字段；顶层 `record_type` 已固定为 `state_transition_event`，不能兼作目标类型。当前原型对 `subject_id` 做多态存在性检查，并对 `record_id` 仅做唯一 ID 解析及警告。建议增加 `subject_record_type` 或统一 `subject_ref: {record_type, record_id}`，此项列为待决设计，不在本轮擅自修改 Schema。
