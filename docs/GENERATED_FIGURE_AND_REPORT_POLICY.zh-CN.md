# 生成图件与报告产物规范

**状态：** 拟议共享规范；经中央 PR 审查并合并后，成为采用该规范仓库的规范性要求。  
**范围：** 项目仓库中生成的科研曲线图、多面板图、图件集合、带注释 PDF，以及其他可复现的可视化/报告派生产物。

本规范补充[计算结果归档规范](CALCULATION_RESULT_ARCHIVAL_POLICY.zh-CN.md)，用于区分规范科研输入与结果，以及仅用于展示这些结果的渲染文件。本规范不改变项目专属物理约定和科学验收标准。

## 1. 核心原则

**归档定义图件的数据和生成程序；日常需要查看时再生成渲染文件。**

如果 PDF、PNG 或 SVG 可以由已经归档的科研数据和有版本控制的绘图程序确定性生成，那么它通常属于展示性派生产物，而不是一项新的科学结果。仓库不应为每一次预览或绘图迭代都累积一份文件副本。

规范记录应保留能够重新生成并科学解释图件的最小完整集合：

1. 绘图使用的源数据和派生数值表；
2. 绘图及 PDF 汇编源码；
3. 绘图配置，以及图件专属的标签、图注、图例定义和面板布局；
4. 将源码版本、输入路径及 SHA-256、运行环境/依赖版本和生成命令绑定起来的清单；
5. 外部数字化参考曲线或其他无法仅凭绘图程序重建的参考数据，并记录来源、提取方法和校验和。

## 2. 默认保留规则

| 内容 | 默认处理方式 | 原因 |
|---|---|---|
| 原始及派生数值数据（CSV、HDF5、ROOT、Parquet、JSON 等） | 以原生格式归档 | 规范科研内容 |
| 比较中使用的外部/数字化参考数据 | 连同来源和提取溯源归档 | 仅凭绘图源码无法重建 |
| 绘图和 PDF 汇编源码 | 归档并进行版本控制 | 定义图件的生成方式 |
| 绘图配置、图注、图例文字、样式和面板定义 | 作为源码/配置归档 | 保证展示可复现、可审查 |
| 运行/图件清单以及输入/输出哈希 | 归档 | 将渲染结果绑定到精确科研输入 |
| 日常 PDF/PNG/SVG 预览和中间版本 | 按需生成，默认不提交 | 可复现的派生产物，避免仓库冗余 |
| 最终冻结的论文图或正式批准的报告 | 作为已批准交付物时归档 | 保留实际提交、审查或引用的精确版本 |

没有提交预览 PDF，不代表图件没有生成或检查。应在相应研究记录或运行清单中记录实际执行的生成和视觉检查状态。

## 3. 哪些情况下应归档渲染后的 PDF 或图像？

满足以下任意一项时，应归档渲染图件/报告快照：

- 它是已提交或已发表论文、学位论文、会议稿件或正式批准报告中实际使用的精确图件；
- 它是正式冻结的阶段性交付物，需要保留其精确外观以供审查或引用；
- 无法从已归档数据和源码可靠重建渲染结果，例如必要的手工标注或专有外部渲染步骤无法用源码表示；
- 外部流程明确要求提交精确的渲染文件。

归档此类快照时：

- 同时保留原生源数据和绘图/汇编源码；
- 记录精确源码 commit、输入哈希、绘图配置、软件/运行环境及相关字体版本、生成命令、输出格式、尺寸/页数和输出 SHA-256；
- 使用稳定的版本化路径或 release 标识；不得悄然覆盖之前冻结的图件；
- 明确标记为冻结展示快照，不将其称为规范数值结果。

不得仅仅因为探索过程中生成过某个中间 PDF/PNG/SVG，就将其全部归档。

## 4. 重新生成要求

绘图工作流应能在干净的项目 checkout 中，通过有文档说明的命令和明确声明的依赖运行。它应当：

- 通过明确路径读取已归档数值数据和参考数据；
- 使用有版本控制的配置，不依赖隐藏的交互状态或未记录的手工修改；
- 将输出写入指定的生成产物目录；
- 保留单位、归一化、坐标轴定义，以及微分率与事件数的区别；
- 使用图例和图注明确标识每条曲线、每个面板和每种物理处方；
- 在缺少必需输入或预期数据列时明确报错；
- 绘图时不修改源数据；
- 生成后记录输出哈希。

对于包含多张图的合并 PDF，应归档汇编程序以及定义页面顺序、图注和图例的文本/配置。除非满足第 3 节的冻结快照条件，否则合并 PDF 按需生成即可。

## 5. CI 与临时预览

- CI 可以生成 PDF/PNG/SVG 供视觉审查，并将其作为临时工作流产物上传。
- 有过期时间的 CI artifact 仅用于预览或传输，不能替代科研数据和绘图源码的规范归档。
- 不要让日常 CI 在每次重生成预览后都提交一套图件。应提交源码、配置、数值数据、清单，以及第 3 节要求保留的冻结渲染快照。
- CI 通过不代表科学结论正确。数值验证和视觉检查应分别记录，且只能记录实际执行过的检查。
- 输入数据哈希或绘图源码 commit 发生变化时，旧渲染结果的溯源关系即不再对应当前版本。将图件用于论文或报告前，应重新生成。

## 6. 审查清单

接受图件生成相关变更前，检查：

- [ ] 每条曲线均能追溯到已归档的数据列或明确记录的解析表达式。
- [ ] 外部/参考曲线具有来源和数字化提取溯源。
- [ ] 绘图源码、配置、图注、图例和依赖均有版本控制。
- [ ] 单位、曝光归一化、率/事件数定义、坐标轴和面板标签明确。
- [ ] 图件能从干净 checkout 重新生成。
- [ ] 任务要求视觉验收时，已经执行视觉检查；记录检查者/时间以及精确输入和源码哈希。
- [ ] 没有不必要地提交日常预览图件。
- [ ] 如需冻结交付物，已连同独立溯源和校验和一起保存。
- [ ] 图件的科学解释没有超出底层已验证结果所支持的范围。

## 7. 项目专属权责与采用方式

- 项目仓库负责保存本项目的图件数据、绘图程序、可视化约定和冻结论文图。
- 中央仓库只维护这份可复用的最低规范及其导航入口，不保存项目专属图件或研究结果。
- 下游仓库通过独立审查 PR 采用本规范，并记录中央仓库完整 commit SHA 及兼容的项目本地扩展。
- 采用本规范不意味着删除或迁移已有冻结论文图和历史图件。新规则适用于新工作和未来修订。

## 8. 与计算结果归档规范的关系

本规范细化了生成式可视化派生产物的归档方式。[计算结果归档规范](CALCULATION_RESULT_ARCHIVAL_POLICY.zh-CN.md)仍然负责原始/派生科研数据、运行溯源、校验和、原生输出、大文件和远端核验。如果某张图本身是不可复现的测量结果或原始数据产品，应将其作为数据归档，而不是视为可丢弃的渲染文件。
