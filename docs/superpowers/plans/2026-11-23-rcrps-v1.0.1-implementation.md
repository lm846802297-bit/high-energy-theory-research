# RCRPS v1.0.1 Unified Source-Control Provenance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` for Native execution or `superpowers:subagent-driven-development` for subagent-driven execution. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement one backward-compatible RCRPS v1.0.1 schema and validator that require complete `execution.source_control` provenance for every new v1.0.1 `run_manifest`, with explicit null PR metadata for non-PR runs and strict checkout-semantic validation.

**Architecture:** Derive the v1.0.1 schema from the adopted v1.0.0 schema, preserving all existing record roles and integrity checks while accepting v1.0.0 records as a compatibility superset. Add a focused semantic validator for cross-field source-control invariants, versioned English/Chinese documentation, regression tests, and the existing structured-result workflow path coverage.

**Tech Stack:** Python 3.12; `unittest`; `jsonschema[format]==4.26.0`; JSON Schema Draft 2020-12; GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-23-rcrps-v1.0.1-unified-design.md`

## Global Constraints

- Main baseline: `b713bfdc971d1118406f619fe3a3fb5c9614e2a7`.
- v1.0.0 schema baseline blob: `8c072cf088e1cab39b0a18411d81682c0cc8ab44`; preserve it byte-for-byte.
- v1.0.0 validator baseline blob: `aee7bdf00ea14f6b562f8a18a9d195d9df9ba7bf`; retain all existing input/output/CSV/hash validation behavior.
- Validation dependency remains `jsonschema[format]==4.26.0`; do not add or upgrade dependencies.
- Every v1.0.1 `run_manifest` must require `execution.source_control`.
- All source-control object keys defined by the approved design are required; non-applicable PR fields are explicit `null`, never omitted or fabricated.
- `source.commit_sha` is the single canonical actual-checkout SHA; do not add a duplicate `checked_out_sha`.
- PR checkout modes are `pull_request_merge`, `pull_request_head`, `pull_request_base`, and `unknown`.
- Non-PR checkout modes are `branch_commit`, `detached_commit`, and `unknown`.
- Preserve existing v1.0.0 manifests and result records byte-for-byte; do not backfill or migrate historical data.
- Keep `docs/STRUCTURED_RESULT_DATA_STANDARD.md` and `docs/STRUCTURED_RESULT_DATA_STANDARD.zh-CN.md` as v1.0.0 documents; update only their validator commands to explicitly select the v1.0.0 schema after the CLI default changes, and add version-specific v1.0.1 documents.

- Do not merge, close, retarget, or rewrite PR #28 or PR #29 as part of implementation.
- GitHub Actions remains optional supporting verification; it is not a scientific-computation engine or a mandatory research gate.
- Merge substantive work through a reviewed PR using the repository's merge-commit policy.

## Review Focus

1. **`pull_request_target` checking out the base branch:** `pull_request_base` must be accepted only when `source.commit_sha == base_sha`; it must not be confused with PR head or synthetic merge. Test: `test_pr_base_checkout_requires_base_sha`.
2. **Non-PR records omitting PR fields or supplying placeholders:** all seven PR-specific properties must exist and be null for non-PR events. Test: `test_non_pr_requires_explicit_null_pr_fields` and `test_non_pr_rejects_non_null_pr_fields`.
3. **PR merge/head/base SHA mismatch:** a valid 40-character SHA is not enough; the correct fields must identify the actual checkout. Tests: `test_merge_checkout_sha_must_equal_source_commit`, `test_head_checkout_sha_must_equal_pr_head`, and `test_base_checkout_sha_must_equal_base_sha`.
4. **Historical v1.0.0 records:** all three record types must validate under the v1.0.1 superset without a source-control object, and the original v1.0.0 schema must remain unchanged. Tests: `test_v100_run_manifest_is_accepted`, `test_v100_result_summary_is_accepted`, and `test_v100_validation_report_is_accepted`.
5. **Checkout-ref, dirty working tree, and workflow metadata inconsistency:** branch/detached checkout modes must agree with checkout_ref; clean/dirty path inventories and workflow run ID/attempt pairs must be internally consistent. Tests: `test_branch_commit_requires_checkout_ref` and `test_detached_commit_requires_null_checkout_ref`, `test_clean_tree_requires_empty_dirty_paths`, `test_dirty_tree_requires_paths`, `test_dirty_paths_must_be_safe_and_unique`, and `test_workflow_run_id_and_attempt_must_be_paired`.

## Interfaces

### Source-control object

The v1.0.1 `run_manifest.execution.source_control` object has exactly these required keys:

- `event`
- `checkout_mode`
- `checkout_ref`
- `pr_number`
- `pr_url`
- `pr_head_sha`
- `base_sha`
- `tested_merge_sha`
- `head_ref`
- `base_ref`
- `workflow_run_id`
- `workflow_run_attempt`
- `working_tree_state`
- `dirty_paths`

### Validator interface

Add:

```python
def verify_source_control(record: dict) -> list[str]:
    """Return source-control provenance errors for v1.0.1 run manifests."""
```

The function returns an empty list for non-run-manifest records and for v1.0.0 records. It validates v1.0.1 source-control cross-field semantics after JSON Schema validation.

The CLI continues to accept explicit `--schema PATH`; its default becomes `docs/schemas/research-result-record-v1.0.1.schema.json`.
